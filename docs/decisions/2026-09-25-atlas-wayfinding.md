# An explicit Atlas Wayfinding mode

The owner authorized Atlas Wayfinding as a directly selectable brainstorming and grilling experience, informed by the shared Atlas library. Repeatedly choosing this conversational style is a useful human entry point. It satisfies the portable-lead decision's criterion for an explicit skill; it does not replace the lead or promote every reference into a public skill.

## Choice and tradeoffs

| Approach | Benefit | Limitation |
| --- | --- | --- |
| Keep only ordinary Atlas discovery | Smallest interface | Leaves deliberate mode selection dependent on inferred intent |
| Install another standalone design workflow | Can provide a focused interaction immediately | Separate conventions can compete with Atlas's authority, continuity and project artifacts |
| Add Atlas Wayfinding backed by shared methods | Direct entry, persistent interaction and access to the existing library | Requires maintaining and checking the distinctive conversational behavior |

The third approach is accepted. The name is **Atlas Wayfinding**, with skill ID `atlas-wayfinding`. Adaptive pacing is the initial default: a consequential question or a compact group of independent choices, with a user-requested pace retained across turns. There is no fixed question count or session length.

## Behavioral boundary

The explicit entry selects an assignment in the main conversation. The shared `wayfinding.md` reference owns its interaction contract; Discover and design continues to own the broader investigation, comparison and readiness methods. Ordinary Atlas can use the mode for a requested brainstorming/grilling session without requiring a separate installed wrapper. Ordinary design advice does not silently acquire the mode.

The visible map distinguishes destination, decisions/evidence, available questions, precise blocked questions, poorly understood territory, deferrals and exclusions. These are semantic distinctions in the existing artifact, not a required schema or new tracker. A question with no answer yet is not automatically fog. Map changes should follow meaningful answers and evidence, while unexamined territory remains visible. Exact headings and a full-map repetition after every reply are unnecessary.

Wayfinding suspends delivery while that discovery assignment is active, including delivery previously authorized. Preserve that earlier scope for resumption. Design agreement alone does not resume execution. A clear user request to implement or resume transitions normally without a special phrase or another approval gate. Pauses, short synthesis requests and partial handoffs remain valid; the mode does not require exhaustive knowledge or endless questioning.

## Preservation and scope

- The host's main agent, tools, permissions and controls remain unchanged. No additional agent profile, runtime, scheduler or workflow controller is introduced.
- Existing lead authority, actual-use notices, selective methods, continuity and continuation/Next guidance remain in force. The mode clarifies the current discovery assignment, rather than creating a general stop rule for Atlas.
- Discover and design retains its existing collaboration, alternative-comparison, omitted-concern and readiness guidance. New routing links expose the focused mode; they do not remove ordinary natural-language discovery.
- One existing approved brief or record owns the map and recovery context. No ticket per question, universal tracker, automatic publication or duplicate ledger is required.
- The new sibling skill depends on the shared Atlas folder. Package metadata advances from 0.9.2 to 0.10.0 for the added entry and mode; current entry points remain compatible.

## Authoring follow-up

The owner subsequently authorized making the transferable writing guidance available to the installed Atlas lead, as well as refining Wayfinding's conversational loop and adding a worked example. One portable writing runbook owns the craft; the maintainer document points to it, and the existing guidance-improvement reference retains diagnosis and evaluation. Relevant authoring requests reach it through the lead and specialist index without another public skill. Donor research is supporting evidence, not accepted policy or a runtime dependency.

The Wayfinding revision makes answer interpretation, dependency updates and next-question selection explicit. Adaptive pacing, partial acceptance, uncertainty, existing records and deliberate transitions remain in force. This scope does not include auditing or rewriting the rest of the library. The combined draft remains a compatible 0.10.0 addition over main 0.9.2.

## Evidence boundary

The [validation record](../validation/atlas-wayfinding.md) separates source review, native activation, useful multi-turn behavior and recovery. A named entry removes the user's need to depend on inferred routing for that invocation; it does not guarantee retention or judgment. Prior discovery misses remain relevant. Small synthetic trials and model reviews cannot establish parity with a person's preferred conversational experience or identical behavior in another host.
