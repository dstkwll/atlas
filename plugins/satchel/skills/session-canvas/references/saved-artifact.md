# Render as a saved artifact

Use in Codex or another host where the agreed surface is a saved file with a preview. Preserve the confirmed interaction and upkeep choices; a static chat diagram is not equivalent to an agreed persistent companion panel.

Use the user's artifact home or the session workspace. Prefer one self-contained HTML file when a browser-style view and inspectable detail are useful; use a simpler supported format when it meets the brief. Keep required assets local or embedded. Reuse the host's visualization tools when they provide the needed behavior, checking whether updates replace the artifact or edit an existing one.

Include the last-assessed point in the visible content. Save enough intent, decisions and evidence references in or alongside the artifact to revise it faithfully, without making a duplicate transcript or prescribed state schema. Stable element identities and small edits can help preserve layout. Keep user content escaped when generating HTML; use safe text rendering rather than executing arbitrary content.

Open the file through the host's actual preview mechanism. In Codex, use `open_in_codex` when offered; it opens a panel but does not by itself prove rendering. Inspect the view with available browser or visual tools. Check labels, narrow-window readability and any interactive details or controls. If inspection is unavailable, state that limit rather than describing the view as verified.

After updating the saved source, check what appears in the open preview. Reload or reopen when needed and supported; do not assume a file write triggers a refresh. If the user must refresh manually, explain that concrete limitation once and preserve the chosen upkeep policy for the source. Preview availability and live reload are host capabilities, not promises supplied by this skill.

Keep direct edits and agent updates coherent. Inspection-only controls need no persistence; content edits need a supported save path and confirmation that it worked before reporting them saved. If that path is unavailable, use chat steering or return the affected interaction choice to the user.

On same-session recovery, find the existing file from session context and inspect its content before updating it. File existence alone does not establish alignment with the conversation. Automatic event-based freshness and cross-session transfer require separate capabilities and evidence; the baseline remains an honest last-assessed marker.
