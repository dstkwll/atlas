# Improve agent guidance from evidence

Use when recurring user corrections, failed tasks or measurable cost/coordination problems suggest the guidance itself needs repair. Start from the original request, actual artifacts and observed result. Frustration, a revert or a low score is a signal to investigate, not proof of a universal rule.

Distinguish an unclear assignment, missing capability, bad guidance, host limitation and implementation mistake. Identify the smallest instruction or routing change that could prevent the demonstrated failure without obstructing valid neighboring tasks. A repeated retry with no new hypothesis does not count as progress. Preserve the full intended outcome when choosing a recovery step.

When instruction relevance or duplication causes the problem, separate enduring constraints from task-specific advice and give the latter a concrete trigger. Keep each rule in one appropriate place and link deeper detail when useful. Before removing prose as tool-enforced, verify that the relevant check is configured, runs on the affected paths and actually enforces the rule. Existing code patterns are evidence, not grounds to erase an accepted exception or obligation. Preserve useful commands and non-discoverable rationale, verifying them before changing or removing them. Use the host's supported instruction format; do not assume a special tag improves adherence without evidence.

Compare the candidate against the baseline using realistic raw artifacts and meaningful counterexamples. Keep protected artifacts inside their approved environment; do not export them for guidance feedback. When independence matters, use a fresh evaluator that did not produce the change. Give it the task and available evidence without coaching the expected answer. Evaluate whether it completes the task, selects relevant guidance, respects authority and reports unavailable evidence honestly. Source inspection and format validity do not prove those behaviors.

Use objective measures where useful and qualitative evidence for judgment. Scores, trial counts and cost reductions are supporting observations; they cannot outweigh a broken requirement. Avoid overfitting to a single fixture or turning one user's preference into global policy. Test that an adjacent ordinary task still proceeds without unnecessary ceremony.

Keep the correction and rationale small and reviewable. Preserve source attribution and the previous candidate so a regression can be understood. Do not generate hooks, regex blockers, automatic policy promotion, a scheduler or a new evaluation service merely to implement a guidance correction. Apply existing authority for enduring project rules and external actions.

Return the diagnosed failure, changed guidance, fresh behavioral evidence, counterexample results and remaining uncertainty. Use the existing continuity record for what a later session needs; no raw transcript vault or compulsory scorecard is required.
