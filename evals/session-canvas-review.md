# Session Canvas checks

These fictional, editor-authored cases exercise discovery, rendering boundaries, updates and an adjacent ordinary request. They are diagnostic examples, not held-out effectiveness measurements. Supply actors only the raw user messages and the actual host/tool constraints, with the candidate skill selected where specified. Keep the review criteria and prior outcomes out of their context. No bookings, contacts, installation or external writes are part of these scenarios.

## Raw session: repair café

Start a fresh conversation, either with no special canvas guidance or with `session-canvas`. The first-turn comparison is conversational; subsequent turns exercise the candidate's saved-file path in a disposable workspace. A file-only trial must disclose the absence of a desktop renderer.

1. “We are planning a neighborhood repair café. We have agreed to hold one Saturday trial, but not a location. The library is free but has no tool storage; the workshop charges $120 but has storage. Priya is actively checking library access rules; I have not started contacting volunteers. We have not picked a site or authorized any booking. I’d like a canvas that keeps me oriented while we work through this session.”
2. “Yes, combined view, chat steering and that cadence work. Please make it. I want the main view to be quick to scan, with reasons I can inspect.”
3. “Priya finished: the library only allows weekday events. Let’s use the workshop so we can keep Saturday and have storage. I still haven’t contacted volunteers, and don’t book anything yet.”
4. “Nothing has changed since that update. I’m still thinking about who to invite.”

Send turn 2 only after the actor offers a compatible brief; record a mismatch rather than treating any fixed follow-up as genuine confirmation. Preserve the initial artifact and changed version before the next exchange. Do not imply the baseline's ordinary response was obligated to follow a skill it never received.

## Raw scope controls

Provide the skill's name/description and allow reading it if selected. The two controls can share a context for a small diagnostic, but then they are not independent trials.

- “I’m early in thinking about a neighborhood learning project and not sure what form it should take. Can we make an evolving canvas while we figure that out?”
- “Show me a small diagram of how a browser request passes through a proxy to a server. This is just for an explanation.”

## Review criteria, withheld from actors

Inspect actual responses, relevant file reads and attributable artifacts. Check whether discovery uses existing facts, offers a useful recommendation and alternative, and waits for brief confirmation before the first render. Sparse project direction should invite focused exploration, not an invented project or a refusal to render until all project decisions are settled. A one-off diagram should proceed without ongoing-canvas ceremony.

For the saved canvas, assess whether a reader can distinguish accepted direction, an open location choice, active investigation and unstarted work. The route-change turn should retain the Saturday outcome, select the workshop with the supplied reason, finish Priya's investigation, preserve unstarted outreach and avoid implying a booking. A no-change exchange should leave those facts intact while identifying the new assessment point; a file write by itself is insufficient evidence that the comparison occurred. Accept alternative readable layouts and status wording.

Challenge any grader with a version that marks the workshop booked and volunteer outreach active, and a valid alternative that shows the same factual state in a simple list. Correctly distinguishing these controls establishes only sensitivity on those examples. Report absent tool traces, source checks, visual inspection, refresh, interaction and recovery separately. Never convert CLI discovery into desktop evidence.

For a live Copilot walkthrough, use a new disposable desktop conversation and session-scoped scaffolding. After the same discovery/confirmation sequence, observe native loading, first render, a meaningful update in the same panel, the assessment marker and same-session reopening. Check any proposed passive signal separately for skipped checks, no-change checks, activity during updates and missing/reconnected event history. Until observed, those behaviors remain unverified; no extra model turns or global installation are required by this test.
