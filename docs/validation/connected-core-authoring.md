# Connected-core authoring pilot

This pilot applies [Writing agent guidance](../writing-agent-guidance.md) to the
shared lead, discovery, Wayfinding and continuity as one connected group. It
preserves accepted behavior while making decisions and their qualifications easier
to find. The charter and accepted architecture remain unchanged.

## Source selection and preservation

The baseline is merged main `14672e9` (0.10.0). The selected source is `ed80e27`
(0.10.1). Both include the complete package; the authoring standard stayed fixed.

| Source | Disposition and reason |
| --- | --- |
| Shared lead | Retained unchanged. Its common authority, routing, continuation and recovery contract was already coherent; splitting its opening paragraph offered limited additional value. |
| Discover and design | Reorganized recurring decisions within the existing conversation section, distinguished whole-approach from slice readiness, and separated probe preparation, stopping and interpretation. Existing explanations, local save reminder and linked parent anchors remain. |
| Wayfinding | Retained unchanged. Its map distinctions, answer/finding loop, example and deliberate delivery transitions already express the intended interaction. Additional local restatements were compatible but unnecessary for this proposal. |
| Continuity and decisions | Put adequate existing artifacts, including HTML, ahead of the new-file fallback; separated decision attribution, direction checks and recovery questions. Project conventions, first-write notice and its no-approval-gate qualification remain connected. |

The most consequential revision decisions concerned relationships, rather than
missing sentences: a project convention can govern before a file exists; an offer
to choose another approved notes location does not require waiting for approval;
and the slice's stopping rule must not replace whole-approach coverage. The final
candidate repairs those interpretation risks while retaining useful local
repetition. An unavailable configured or established destination remains distinct
from having no destination, where the existing safe fallback can apply.

Native Copilot authors used verified Astra/max and Opus 5.5/xhigh for one draft,
one reciprocal critique and one separate revision each: six completed attempts,
with no additional candidate rounds. Both initial drafts froze before peer access;
both critiques froze before revisions. Complete original sources, accepted
decisions and relevant actual Git patches remained available every round. Peer
review and revision received the frozen full candidates.
The selected two-reference proposal uses Astra's organization after corrections
prompted by Opus's critique. The lighter four-file alternative and baseline
retention were considered; combining fragments was not required.

All attempts stayed within their file scopes. One initial author could not save
analysis files because the temporary output directory was absent; its attempted
content and full response were retained, and the scheduled revision had a usable
directory. That author's required source coverage remained incomplete and is not
credited as a full preservation audit. Reports were checked against actual source
and execution evidence rather than accepted as proof. Peer-informed convergence
is not independent corroboration or a model-quality benchmark.

A fresh reviewer derived requirements from the originals before seeing the
candidate or producer reasoning, then read all four final sources and affected
relationships. It found no actionable preservation, authority or scope defect.
The 83 links touching these sources resolve. This establishes inspected source
eligibility, not behavioral equivalence.

## Native behavior comparison

The fixed comparison used two three-turn scenarios against both sources in native
Codex and Copilot: eight trials, one per condition, with returned Astra/medium
settings and a 360-second bound per trial. Both sources, prompts, fixtures and
reviewer-only criteria were frozen before inference. All eight completed; none
was retried or replaced because of its behavior. Authoring used the higher efforts
above; behavioral validation is limited to Astra/medium.

| Scenario | Observations in both sources and both hosts |
| --- | --- |
| Changing calendar design | Used actual export limitations to challenge an availability promise; compared credible approaches; followed a changed goal and partial acceptance while leaving visibility policy open; distinguished precise questions, dependent presentation and unresearched user needs. Only the existing HTML planning record changed. |
| Paused correction and fresh-session recovery | Suspended previously authorized delivery for Wayfinding; preserved exact-label rationale and unresolved wider design; obeyed the short checkpoint; recovered current sources in a distinct fresh session; then completed only the explicitly resumed correction, with a native regression that failed before the fix and passed afterward. |

All four recovery checkpoints stayed below 120 words, counting commentary and
final text together, and introduced no question. Each correction rejected only
an exactly empty title, retained every nonempty string's existing return path,
and left retention unchanged. Source/tests stayed untouched during the design
turns. Final records distinguished completed narrow delivery from open wider
design. The fresh sessions retained project artifacts, not the earlier dialogue;
this exercises artifact recovery, not compaction or recovery from the note alone.

Review considered visible responses, actual tool attempts/results and intermediate
records, rather than host completion or a final accurate summary alone. Codex
intermediate HTML was reconstructed from successful patches and checked against
per-turn hashes; Copilot retained full per-turn contents. Separate objective probes
were distinguished from the agent's actual test executions. Independent reviewers
examined recovery and Copilot traces; the coordinator reviewed Codex calendars
and verified material recovery observations.

One localized record-fidelity caution remains: Copilot with the revised source
briefly saved that the methods require one consequential question at a time.
Atlas permits an adaptive question or small related group. The sentence survived
the checkpoint and was replaced on delivery; this script did not exercise a
consequence of that narrowing. It is retained as an observation, not dismissed by
the successful correction or attributed causally to the rewrite.

Both baselines also behaved usefully, so these observations do not demonstrate
improvement. Calendar arms chose different valid next questions: some advanced an
independent phone-preparation choice while others deepened visibility's effect
on enquiries. The fixed script does not establish which would work better in a
longer real conversation. Planning records grew substantially in both sources;
there is no demonstrated reduction in context or artifact burden.

Activation explicitly selected Atlas and requested Wayfinding in ordinary text;
models also consulted its wrapper. This is not a generic implicit-selection test.
Native Codex bundled reads were sometimes clipped. Targeted reads recovered
affected methods, but one baseline recovery read clipped the lead's tail without
a separate reread of that passage. Native Atlas skill activation is separately
recorded; this limits explicit reread coverage without establishing that active
guidance was missing. Consultation evidence does not guarantee loading across hosts.

## Checks and limits

The 39 evaluator correctness tests pass. Package and marketplace versions align at
0.10.1; the final diff and core links were checked. These checks establish their
stated structural properties, not model adherence.

The rewrite adds navigation rather than reducing the information required by the
loaded path. It is not a full-library audit, proof that every implicit connection
survives, or evidence of better performance across models. Long-session drift,
compaction, workplace/IDE activation, autonomous method discovery and broader
specialist composition remain outside this pilot. Source snapshots, complete
author artifacts, trial actions and detailed review remain local maintainer
evidence; [reusable cases](../../evals/README.md) and
[semantic expectations](../../evals/core-authoring-review.md) are public. The final
validation-document commit changes no tested product bytes.
