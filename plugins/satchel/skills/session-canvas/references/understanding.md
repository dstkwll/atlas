# Explain what matters to the route

Use when orientation depends on understanding relationships, causes, boundaries or reasons. Choose a concept map, system sketch, annotated flow or focused explanation according to the user's question.

Include the relationships that change how the user understands the work or makes the next decision. Label what arrows mean: dependency, information flow, sequence and causality are different claims. Ground explanations in available evidence; distinguish an observed fact, a useful simplifying model and an untested explanation. Link supporting evidence where the user can inspect it without crowding the overview.

For a combined canvas, connect explanation to the work or choice it illuminates. A storage constraint might explain why one venue needs extra transport planning. It is not itself a task or an established reason to select the other venue. A software component map may explain a blocked integration without needing a complete architecture diagram.

Give important uncertainty enough prominence that a polished visual does not imply certainty. On revision, remove explanations that no longer help and retain reasons for consequential choices. A focused visual explanation skill can help if available, but this guidance works without one.

Check that a reader can follow the relevant relationship and tell which claims remain uncertain. Avoid expanding the canvas into a general encyclopedia of the project.
