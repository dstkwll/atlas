# Specialist methods: observations and pending validation

The change adds product-interface review, user research/feedback synthesis,
quantitative visualization and conditional model post-training methods. Existing
security/data lifecycle, recovery, localization/CLI, cost, retrieval and verification
methods gain focused checks. Routes appear in the lead, specialist index and
relevant guides. The existing charter and portable-lead decision already support
selective methods; product direction is unchanged. No runtime, prescribed staff,
tool dependency or universal stage is added. Package 0.9.0 reflects capabilities.

## Intended selection boundaries

| Method | Intended trigger | Important neighboring boundary |
| --- | --- | --- |
| Product interface review | New/revised screen, hierarchy/workflow/clarity critique | Mechanical copy changes need no design menu; source is not rendered evidence |
| User research | Study planning, feedback synthesis, decisions dependent on actual users | Owner preferences and simulated personas are not participant evidence |
| Quantitative visualization | Quantitative encoding affects interpretation | Arithmetic lookup and nonquantitative diagrams need no chart audit |
| Model post-training | Fine-tuning, training signal or checkpoint integrity | Inference/retrieval changes need no training investigation by default |
| Security | Changed/uncertain identity, permissions, credentials, private-data lifecycle, model/tool authority or sensitive input boundary | Public endpoint wording alone does not warrant review |
| Data and migrations | Persistence, deletion/retention, backup/restore and recovery claims | Reading recorded backup status is not readiness assessment |
| User journeys | Interaction, accessibility, localization, CLI/script users | Source findings are separate from unavailable device execution |
| Performance | Slowness, resource growth or unit-cost regression | More total spend can reflect more useful work |
| Model/retrieval quality | Candidate generation versus ranking failures | Ranking cannot recover an upstream-excluded item |
| Project verification | Repeatable checks and incomplete/retried/sharded evidence | A green summary does not prove missing coverage |

## Evaluation design and structural checks

The [21 scenarios](../../evals/cases.json) use natural requests and synthetic raw
artifacts. [Semantic expectations](../../evals/specialist-review.md) remain outside
executing workspaces. Consultation, useful application, selectivity and authority
are separate judgments. Nineteen scenarios were prepared independently of the
implementation wording. Two Security diagnostics follow a source-review finding
and are not held out. There are four negative controls and an interface-to-feedback
transition. Transition files exist initially and follow-ups are fixed, so this is
not an unpredictable human conversation.

All 39 evaluator correctness tests passed, as did skill validation, local-link and
diff checks. No prose-matching grader or runtime was added. These checks establish
structure and evaluator sensitivity, not agent judgment.

Independent source review found a Security entry condition broader than its
routing rows and then a missing explicit permission cue. Both were corrected;
fresh source inspection verified the selective condition and mechanical-edit
exclusion. Native selectivity on the final condition remains to be tested.

## Native observations

**25 attempts were retained: 16 host-completed samples, covering 20 turns, and nine
blocked/interrupted attempts.** Eight completed samples used main; eight used
candidate revisions, including two retained-behavior cases and six new scenarios.
Host completion is not a behavioral pass. All attempts reported stopped hosts and
removed temporary authentication homes.

The main/candidate subset used matching requests, fixtures, host, model and effort
with explicit project-local Atlas activation. Per-attempt source identities remain
in local evidence. Earlier results are not reassigned to later instruction edits.

| Completed coverage | Independent observation |
| --- | --- |
| Retained visible design and Performance/Types activity triggers | Candidate consulted relevant methods, compared viable approaches and preserved unresolved judgment across follow-ups |
| Interface critique | Candidate read Product interface review and connected hierarchy, dates and request semantics to the task; main also found key issues. Both omitted the fixed-width/mobile concern |
| Interface proof reporting | Candidate announced viewport checking but only discovered tools and inspected source. Its final answer omitted the unavailable-rendering limit, without explicitly claiming successful rendering |
| Mechanical copy control | Main and candidate returned the exact correction without a specialist sweep |
| Feedback | Main and candidate distinguished duplicated incidents, sessions versus people and simulated personas, with bounded recommendations |
| Activity transition | Candidate selected User research after the task changed from interface critique to feedback; baseline also usefully changed its analysis |
| Post-training | Candidate read the new method and diagnosed truncated-away preference responses without extrapolating the sample to the whole corpus or claiming training; baseline also diagnosed the issue |
| Deletion/recovery | Main and the serial candidate replacement traced resurrection and falsely completed downstream deletion. Candidate used Data/migrations; this does not prove Security consultation |
| Baseline study planning and chart interpretation | Main already produced materially useful results, limiting claims that new guidance was necessary or superior |

The interface guide now requires the final response to distinguish source,
rendered and exercised coverage and disclose unavailable announced checks.
Independent source review found this amendment coherent. Its behavioral effect
has **not** been retested; the original mobile/disclosure misses remain recorded.

## Interrupted and outstanding checks

Six attempts were interrupted by storage errors while capturing evidence. Three
more failed during host startup; one explicitly reported inability to initialize
SQLite state. This does not establish the cause of every startup error. A serial
deletion replacement completed, but the following serial startup failed. Further
inference stopped. Original attempts remain alongside replacements.

Fifteen new scenarios lack a completed candidate sample: study planning,
prospective sensitive collection, identity revocation, recovery readiness/status,
chart interpretation/arithmetic control, localization, CLI, model-tool authority,
unit cost, retrieval candidates, test-result reconciliation and both Security
diagnostics. Revised interface disclosure also needs fresh behavioral evidence.

Resume these prepared cases when the host can reliably retain state and traces,
then independently inspect reads, responses and artifacts. Preserve earlier
failures and label replacements. Use fresh cases for claims extending beyond
examples already inspected or used for tuning.

These synthetic tasks do not establish rendered UI behavior, actual participant
research, database restore, live account administration, training or production
readiness. Explicit activation does not test implicit host discovery. Single
samples and reviewer agreement do not establish reliability across models, hosts
or real conversations. This remains a draft integration with incomplete
behavioral acceptance.
